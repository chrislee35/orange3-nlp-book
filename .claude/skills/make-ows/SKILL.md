# Building .ows workflows

Workflows are generated by `utils/make_ows.py` (run with the Orange env:
`~/code/miniconda3/envs/orange/bin/python utils/make_ows.py [name] --check`).
Output goes to `workflows/`. The user opens the file in Orange and reports what's wrong; fix it in the script, not by hand-editing the .ows.

## Adding a workflow
1. Write a function returning `build(nodes, links, annotations)`:
   - node = `(key, widget, title, (x, y), settings_dict)`; link = `(source_key, sink_key)`.
   - Register it in `WORKFLOWS`.
2. If a widget or link pair is new, add it to `WIDGETS` / `LINKS`. Get module paths and channel ids by introspecting the class:
   `W.get_signals("inputs"|"outputs")` gives `(name, id)`; qualified name is `W.__module__ + "." + W.__name__`.
   Existing .ows files in `workflows/` are also good references.
3. Run with `--check`: it loads the file via Orange's own `scheme_load` and prints node/link counts and errors. Passing means it parses, not that it looks right.
4. Ask the user to open it and send a screenshot.

## Settings
- Stored as pickled dicts (`format="pickle"`). Only set what's needed; the rest falls back to widget defaults.
- Known: Corpus `recent_files` = [absolute path] loads that file; Distances `axis` 0=rows, `metric_id` 4=Cosine.
- Not settable here (context settings): which column is the text feature, t-SNE color/label, Hierarchical Clustering label/color. List these in an annotation so the reader sets them in the GUI.

## Layout lessons (from user feedback)
- Grid: ~150 px between columns' rows, ~225 px between columns. Share one SBERT Embedder across chains when sensible.
- Put annotations in an empty corner (e.g. top right), never in the middle: links and nodes are drawn over/under them.
- Give every node a distinct title (e.g. "Distances B (cosine)").
- Corpus paths are absolute; mention that they need re-pointing on another machine.

## Widget gotchas
- *Data Table* sends **all rows** when nothing is selected. Wired into *Neighbors* as Reference, this shows "Every data instance is same as some reference" until a row is selected. Expected, and mentioned in ch12 12C.
- Titles are not settings. A node titled "(cosine, 5)" still runs at widget defaults unless the settings dict sets them (Neighbors: `n_neighbors`, `metric_id` 4=Cosine in its own metric table). Check each titled option actually appears in the settings.
- *Corpus* uses **all** string columns as text by default (BBC3: Title + Content joined), and *Text Embedder* embeds that joined text. Two branches meant to embed different columns give identical results unless each Corpus's "Used text features" is set. The choice is a context setting the script cannot preset, so state it in the chapter steps and the workflow note.
